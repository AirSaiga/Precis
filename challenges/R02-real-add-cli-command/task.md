## 任务

Precis 后端有一个**自定义** CLI 框架（不是 click / argparse / typer，而是自行实现的
交互式 Shell）。新增一个 `version` 命令，打印当前 Precis 的版本信息。该命令必须**完全
可用**：实现命令类、注册到 CLI 框架、可通过命令行调用、返回包含版本号的字符串。

自己找到 CLI 框架的所有相关文件——框架是分散注册的，遗漏任何一处注册点都会导致测试失败。

### 命令行为

```
precis> version
```

执行后应返回成功结果，其消息为**非空字符串**且**包含版本号**（例如 `0.1.0` 这类语义化版本）。

### 版本来源

Precis 是一个已安装的 Python 包，包元数据里记录了版本号。请用读取包元数据的标准方式
获取版本（仓库内已有同样的读取方式可供参考，自己找）。**不要**硬编码版本号字符串。

## 约束

- 在真实仓库代码里找到 CLI 框架的所有相关文件，完成**实现 + 注册**。
- 命令类必须**遵循框架既有的 Command 契约**（抽象基类定义的属性与方法）。
- 命令名必须是 `version`。
- **不得**修改 `challenges/` 目录、**不得**修改 `tests/` 目录（verify 脚本会自行放置测试文件）。
- 参考已有命令（如 `exit`、`validate` 等）的实现与注册模式——自己找。

## 验证

在本目录运行：

```
python verify.py
```

`verify.py` 会把测试文件复制进后端测试目录并以 pytest 运行。
退出码 `0` = PASS，非 `0` = FAIL。stdout 首行为 `PASS` 或 `FAIL`。

## 提示

- 先找到"命令基类"（抽象基类），看清 Command 契约定了哪些必须实现的成员。
- 一个命令要"可用"，至少要接通两处：**命令集合包的导出**与**Shell 启动时的注册调用**。
- 注册不是自动的——Shell 主类在初始化时逐条 `register`，漏掉这一步命令虽然存在但调不到。
- 版本号读取：搜索仓库里已有"读取包版本"的代码片段，复用同一套方式（带 fallback）。
