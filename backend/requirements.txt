# ============================================================================
# Precis 后端运行时依赖锁定清单
# ----------------------------------------------------------------------------
# 用途：为 Electron 打包提供离线/可复现的传递依赖快照（install-backend-deps.js
#       用内嵌 Python 解释器 pip install -r 本文件，把依赖装入运行时 site-packages）。
#
# 注意：
# - 本文件只应包含【第三方运行时依赖】及其传递依赖。
# - 禁止出现 -e 可编辑安装：precis 自身包在打包环境由 start_server.py 的 sys.path
#   注入提供，在开发环境由 `pip install -e .` 提供，永远不该写进 requirements.txt。
# - 开发工具（pytest/ruff/mypy/pip-audit/twine/pyinstaller 等）请通过
#   `pip install -e ".[dev]"` 安装，不要冻结到本文件，避免被打进用户安装包。
#   （2026-10 曾因在装了开发工具的 venv 里直接 freeze，混入 62 个泄漏包，已清理。）
# - 重新生成本文件（推荐"约束法"，保持既有版本零漂移）：
#     1. 干净 venv：python -m venv .tmp-reqgen
#     2. cp backend/requirements.txt /tmp/constraints.txt   # 旧清单作约束
#     3. cd backend && pip install -e ".[full]" -c /tmp/constraints.txt
#     4. pip freeze --exclude-editable > 新清单
#   两个已知陷阱：
#   a) 必须用干净 venv——venv 里装过的开发工具会被 freeze 一并冻结进来；
#   b) pip freeze 不输出平台 marker——Windows 上 freeze 会产出 pywin32 这类
#      win 专属包（mcp 的条件依赖），须手工补 `; sys_platform == 'win32'`，
#      否则 macOS 打包 CI 安装失败。pyreadline3 纯 Python 无害，保持无 marker。
# - 本清单是 [full] extra（api/ai/completion/mcp）的闭包：pyproject 新增依赖后
#   必须同步重新生成本文件，否则打包版缺包（2026-10 曾漏 xlrd/mcp 闭包）。
# ============================================================================
